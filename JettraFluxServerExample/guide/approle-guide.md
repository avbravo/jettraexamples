# Guía de Configuración y Uso de `jcf.AppRole` en Jettra

Esta guía explica la arquitectura, configuración y uso del enum `jcf.AppRole` generado automáticamente por `JettraAppServer` a partir del archivo de configuración `jettra-config.properties`.

---

## 1. Visión General

Anteriormente, los roles de seguridad en las anotaciones `@PageWidgetAllow` y `@ActionWidgetAllow` se definían utilizando arreglos de `String` (por ejemplo: `role = { "ADMIN", "MANAGER" }`). 

Con el nuevo esquema:
- Se define la lista de roles en la propiedad `app.roles` dentro de `src/main/resources/jettra-config.properties`.
- `JettraAppServer` lee esta configuración y genera de manera automática el enum `jcf.AppRole`.
- Las anotaciones `@PageWidgetAllow` y `@ActionWidgetAllow` utilizan directamente `jcf.AppRole` (por ejemplo: `role = { jcf.AppRole.ADMIN, jcf.AppRole.MANAGER }`).

---

## 2. Configuración en `jettra-config.properties`

En el archivo `src/main/resources/jettra-config.properties` de tu proyecto, define los roles permitidos en la propiedad `app.roles` separados por comas:

```properties
app.roles=ADMIN, MANAGER, USER
```

---

## 3. Generación Automática por `JettraAppServer`

`JettraAppServer` cuenta con la clase `io.jettra.server.config.AppRoleGenerator` integrada en el ciclo de vida de configuración (`JettraConfig`).

### Funcionamiento:
1. Al cargar la aplicación o iniciar el servidor, `JettraConfig` lee la propiedad `app.roles`.
2. `AppRoleGenerator` procesa la lista de roles y genera automáticamente el código fuente en `src/main/java/jcf/AppRole.java`.
3. El archivo generado tiene la siguiente estructura:

```java
package jcf;

/**
 * Auto-generated by JettraAppServer from jettra-config.properties.
 */
public enum AppRole {
    ADMIN,
    MANAGER,
    USER;

    public String getValue() {
        return name();
    }
}
```

---

## 4. Uso en Anotaciones

### A Nivel de Clase (Páginas / Vistas)

Usa `@PageWidgetAllow` con los valores del enum `jcf.AppRole`:

```java
package com.flux.plugin.example.pages.example;

import io.jettra.core.security.widget.PageWidgetAllow;
import io.jettra.core.server.Page;
import com.flux.example.pages.template.TemplatePage;
import jcf.AppRole;

@PageWidgetAllow(role = { jcf.AppRole.ADMIN, jcf.AppRole.MANAGER })
@Page(path = "/person")
public class PersonPage extends TemplatePage {
    // ...
}
```

### A Nivel de Método (Acciones)

Usa `@ActionWidgetAllow` en métodos del controlador o página:

```java
    @ActionWidgetAllow(role = { jcf.AppRole.ADMIN, jcf.AppRole.MANAGER })
    private void saveForm(HttpExchange exchange, Map<String, String> params) {
        // Lógica protegida de la acción
    }
```

---

## 5. Ventajas Principales

1. **Seguridad en Tiempo de Compilación**: Evita errores tipográficos al escribir nombres de roles como cadenas de texto.
2. **Autocompletado en el IDE**: Los IDEs (NetBeans, IntelliJ, Eclipse, VS Code) proveen autocompletado y validación de tipos inmediata durante la edición del proyecto.
3. **Sin Conflictos de Edición**: El archivo `jcf/AppRole.java` reside directamente en el árbol del proyecto (`src/main/java/jcf/AppRole.java`), garantizando que la edición y compilación se realicen limpiamente sin errores de símbolos no encontrados.
